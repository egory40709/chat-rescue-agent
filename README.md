# Chat Rescue Agent 1.2.0

**Автоматически скачивает переписки по одной из открытой сессии ChatGPT/Claude.**

Сбор работает через список истории: собирает ссылки → открывает первый диалог →
сохраняет его сообщения в Markdown и JSON → переходит к следующему → собирает ZIP.
**Кнопка «Экспорт данных» в настройках не используется и не требуется.** Если её нет
в рабочем пространстве Team/Business, для этого механизма ничего не меняется.

Сотрудник уже вошёл в нужный аккаунт. Инструмент подключается к этому браузеру,
создаёт свою рабочую вкладку в том же профиле, сохраняет прочитанные чаты в Markdown
и JSON и собирает ZIP. Повторного входа, ручного Enter и команды «продолжить» в
основном режиме нет. Браузер сотрудника после работы остаётся открытым.

Управление — через локальный MCP или команды с JSON-ответами. Это локальная программа;
сотруднику не требуется устанавливать расширение или переносить аккаунт на сервер.

## Что передать своей ИИ

Дайте папку/репозиторий локальному агенту с доступом к компьютеру и запрос из
[PROMPT.txt](PROMPT.txt):

> Прочитай AGENTS.md и выгрузи мои доступные чаты ChatGPT/Claude. Я уже вошёл в
> браузере. Запусти `node agent.mjs scrape`: скачай чаты по одному и дай ZIP.
> Кнопку «Экспорт данных» в настройках не используй.

Агент сам устанавливает зависимости, запускает инструмент и следит за очередью.
Одна ссылка на репозиторий в обычном веб-чате без локального выполнения кода не
запускает программу на компьютере сотрудника.

## Быстрый запуск

Нужен Node.js 22+. В папке репозитория:

```sh
npm ci
node agent.mjs scrape --provider chatgpt --workspace work
```

Для Claude — `--provider claude`. `workspace` — метка архива, а не пароль.
Архив по умолчанию находится в `Downloads/chat-rescue/<сервис>/<метка>-<хеш>/`.
Отдельную папку задаёт `--out "/путь/архив"`. Для двух сервисов запускайте две
последовательные выгрузки с разными папками.

`scrape` (совместимые команды: `export` и `start`) возвращает `run_file`, а worker продолжает работать.
Сразу после подключения начинается поиск и сохранение. Агент опрашивает:

```sh
node agent.mjs status --run "/путь/архив/run.json"
```

В конце доступны `zip.path`, `zip.sha256`, `index_file` и счётчики. Содержание
чатов не возвращается в ответы MCP/CLI: оно записывается только в локальные файлы.
После окончания:

```sh
node agent.mjs close --run "/путь/архив/run.json"
```

Закрываются только рабочая вкладка и соединение инструмента. Исходная вкладка,
другие окна и текущий вход сотрудника сохраняются.

## Разрешение подключиться к открытому браузеру

Вход в аккаунт и разрешение управления браузером — разные вещи. Вход повторять
не нужно, но браузер может потребовать подтвердить подключение инструмента.

**Chrome 144+ (Windows, macOS, Linux):** откройте в своём уже запущенном Chrome
`chrome://inspect/#remote-debugging`, включите доступ и подтвердите запрос подключения.
Инструмент читает только файл метаданных DevToolsActivePort и подключается к
опубликованному локальному WebSocket. Он не читает базу cookies и не копирует профиль.
[Официальный способ Chrome для существующей сессии](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session).

**macOS:** если CDP недоступен, есть штатная автоматизация Chrome/Edge через Apple
Events. Может потребоваться разрешение в macOS и пункт браузера «Вид → Разработчик →
Разрешить JavaScript из событий Apple». Эти настройки инструмент сам не меняет.
Системное разрешение и нативный интерфейс Apple Events зависят от вашего браузера.

Если локальный CDP уже разрешён, его можно явно указать:

```sh
node agent.mjs scrape --provider chatgpt --workspace work --cdp http://127.0.0.1:9222
```

Поддерживается и локальный `ws://127.0.0.1:…/devtools/browser/…`. Удалённые адреса,
встроенные credentials и перенаправление на другой сервер отклоняются. Новые CDP
порты инструмент не открывает и браузер не перезапускает.

Если подходящих вкладок несколько, выбирается активная. При неоднозначности
возвращается `source_tab_required` со списком ID; сделайте нужную вкладку активной
либо укажите `--source-tab ID`. Для Edge на macOS укажите `--browser msedge`.
Текущий workspace определяется исходной вкладкой: перед запуском выберите нужный.
Во время чтения не меняйте аккаунт/пространство в браузере.

Если разрешение не выдано, вкладки нет или сессия закрыта, возвращается конкретная
ошибка. Новый пустой профиль/окно входа вместо неё автоматически не запускается.
Сессия только внутри настольного приложения ChatGPT/Claude не является вкладкой
Chrome: этот режим использует уже авторизованный аккаунт в обычном браузере.

## MCP

Локальный stdio-сервер:

```sh
node mcp.mjs
```

Готовый конфиг с абсолютными путями текущего компьютера:

```sh
node agent.mjs config
node agent.mjs config --client codex
```

Для Codex: [официальная документация](https://learn.chatgpt.com/docs/extend/mcp).

```sh
codex mcp add chat-rescue -- node "/ABSOLUTE/PATH/chat-rescue-agent/mcp.mjs"
```

Для Claude Code: [официальная документация](https://code.claude.com/docs/en/mcp).

```sh
claude mcp add --transport stdio chat-rescue -- node "/ABSOLUTE/PATH/chat-rescue-agent/mcp.mjs"
```

Агенту достаточно вызвать `open_export_session({provider, workspace})`: по умолчанию
`connection=existing`, `auto_start=true`. Он получает job_id и опрашивает
`get_export_status`. Дополнительные `start_export` и `user_ready` не требуются.
`close_export_session` отключает инструмент, сохраняя браузер сотрудника.
Для диагностики: `auto_start=false` только подключает, `inspect_export_session`
показывает метаданные; позднее `start_export` в existing режиме работает без
подтверждения входа.

Доступны прежние stop_export, resume_export, create_export_zip и check_environment.
Ошибки подключения возвращаются с машиночитаемым `code`. Полные чаты в ответы
инструментов не включаются. Существующие настройки AI-клиента сами не меняются.

## Skills из Codex и Claude

Отдельная команда сохраняет Skills целиком, включая `SKILL.md`, `scripts`,
`references`, `assets` и бинарные шаблоны. Код из Skills не выполняется.

```sh
node agent.mjs skills --provider all
```

`all` проверяет локальные Skills Codex, Claude Code и веб-раздел Claude
`Customize → Skills`. Веб-сбор использует уже открытую вкладку Claude: по очереди
открывает найденные Skills и нажимает их **Download**, сохраняя оригинальные ZIP.
Это скачивание конкретного Skill, а не штатный экспорт данных аккаунта.
Если Claude недоступен, локальные Skills всё равно сохраняются, а отчёт содержит
ошибку веб-сбора. Пустой или недоступный список не считается подтверждением полноты.

Можно выбрать источник:

```sh
node agent.mjs skills --provider codex
node agent.mjs skills --provider claude-code
node agent.mjs skills --provider claude-web
node agent.mjs skills --provider local
```

`codex` ищет `~/.agents/skills`, `$CODEX_HOME/skills` (обычно `~/.codex/skills`),
проектные `.agents/skills` / `.codex/skills` от текущей папки до Git-корня, а также
папки Skills в локальном кэше плагинов. Claude Code — `~/.claude/skills`, проектные
`.claude/skills` и его кэш плагинов. Кэш может содержать несколько версий: они
сохраняются отдельно, без утверждения, что все версии сейчас активны.
[Пути Codex в OpenAI Docs](https://learn.chatgpt.com/docs/build-skills).

`--project /path/project` задаёт исходный проект. `--skills-dir /path/skills`
(можно несколько раз) заменяет автоматический поиск явно указанными каталогами.
`--no-plugins` исключает кэш плагинов; `--include-system` добавляет локальные
системные Skills и `/etc/codex/skills`. `--out /path/backup` задаёт папку результата.
При повторном сохранении в ту же папку создаётся новый подкаталог, старый ZIP остаётся.

Результат: отдельный ZIP на каждый Skill, общий `skills-backup.zip`, `INDEX.md`
и `manifest.json` с именами файлов, SHA-256, источниками и пропусками. Отдельные ZIP
можно распаковать в локальный каталог Skills или загрузить в Claude. В JSON-ответе
CLI/MCP есть только метаданные, без содержимого инструкций.

В MCP: `start_skills_export({source: "all"})` → `get_skills_export_status({job_id})`.
Есть `stop_skills_export`; после остановки сохраняется архив уже полученных пакетов.
В CLI команда работает без TTY и возвращает финальный JSON; агенту нужно дождаться
завершения процесса. По умолчанию архивы находятся в `Downloads/chat-rescue/skills/`.

Веб-сбор не обещает выгрузку всех общих, встроенных или закрытых Skills: нужен
доступный в интерфейсе Download. Изменившийся интерфейс, отказ, внешний URL скачивания
или неподдерживаемый ZIP показываются в отчёте. Нет скрытых API endpoint и обхода
прав. Один веб-пакет ограничен 16 МБ, локальный Skill — 128 МБ, общая копия — 256 МБ.
Настоящие `.env` и файлы авторизации аккаунта исключаются; шаблоны `.env.example` /
`.env.template` / `.env.sample` сохраняются. `.git`, `node_modules` и виртуальные
окружения пропускаются. Внешние симлинки внутри Skill пропускаются с отметкой;
симлинк самой папки Skill поддерживается. При пропусках статус `partial/needs_review`.

Живое скачивание Skills из корпоративного Claude пока не проверено. Браузерные
проверки используют настоящие ZIP и Chromium с искусственными страницами.
[Официальная инструкция Claude по Skills](https://support.claude.com/en/articles/12512180-use-skills-in-claude).

## Остановка, продолжение и выбор ссылок

```sh
node agent.mjs stop --run "/путь/run.json"
node agent.mjs resume --run "/путь/run.json"
node agent.mjs pack --run "/путь/run.json"
```

`stop` останавливает очередь, `resume` продолжает с проверкой SHA-256,
`pack` упаковывает уже сохранённое без чтения сайтов. После завершения worker можно
снова подключиться с теми же provider/workspace/out. Повторный поиск добавит новые
доступные ссылки, а сохранённые чаты проверятся по контрольным суммам.

Для одной открытой переписки: `scrape --mode current`. Для известного списка:
`scrape --urls-file links.txt` (одна HTTPS-ссылка в строке). В MCP используйте
`initial_options: {mode: "current"}` или `{mode: "urls", urls: [...]}`.
`--refresh` перечитывает выбранные чаты с сохранением предыдущих версий.
`--max-scrolls` и `--list-scrolls` допускают до 5000 шагов; `--delay-ms` — минимум
1000 мс между чатами. `--limit` ограничивает число новых чтений за запуск.

Режим отдельного профиля оставлен только по явному выбору:
`node agent.mjs start --isolated ...` или MCP `connection=isolated`. Именно в нём
возможен `awaiting_login` и потребуется вход в отдельном окне. Основной режим его
не использует и автоматически в него не переключается.

## Что сохранено и что проверено

В папке: `chats/*.md`, `chats/*.json`, версии, `INDEX.md`, `manifest.json`, ZIP.
`run.json` и служебные команды не попадают в ZIP. Архив содержит EXPORT-ISSUES.json
с результатом проверки целостности. В статусе `extraction_method=rendered-ui-v1`, `native_export_required=false`.
Статусы: ready/discovering/exporting,
complete/needs_review/paused/blocked/failed; specific connection errors — в error_code.

`complete` означает окончание выбранной очереди. Полнота всего аккаунта, архивных
и проектных списков автоматически не подтверждается. Сохраняется отображённый текст
выбранной ветки; вложения, картинки, Canvas/Artifacts, скрытые блоки и другие ветки
нужно скачать отдельно. Отключённый корпоративный доступ не восстанавливается.

Живое чтение корпоративных чатов пока не проверено. В тестах уже существующая
авторизованная сессия воспроизводится с искусственной cookie и offline-страницами;
это проверка механики повторного использования входа, а не ваших аккаунтов.
Подробности — [QA.md](QA.md).

```sh
npm test
npm run build
```

Нет платных AI/API вызовов, загрузки архивов на сервер или копирования cookies.
