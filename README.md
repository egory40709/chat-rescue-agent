# Chat Rescue Agent

**Дайте этот репозиторий локальному AI-агенту и попросите сохранить свои рабочие чаты.**
Готовый инструмент сам ищет доступные переписки ChatGPT/Claude, проходит очередь,
проверяет сохранённые файлы и создаёт ZIP. Управление — через команды с JSON-ответами
или настоящий MCP stdio. Браузерное расширение не требуется.

Сотрудник выполняет вход в аккаунт и выбирает рабочее пространство в отдельном
браузере. После сообщения «вошёл, нужное пространство выбрано» агент продолжает сам.
Пароли и cookies не передаются в чат или аргументы команд.

## Что дать сотрудникам

Передайте папку/репозиторий и этот запрос, либо содержимое [PROMPT.txt](PROMPT.txt):

> Прочитай AGENTS.md и сохрани мои доступные рабочие чаты ChatGPT и Claude через
> готовый инструмент. Сам установи зависимости и запусти браузер. Я войду и выберу
> пространство. После моего сообщения продолжи сам и дай ZIP с отчётом.

Подходит агент с **локальным терминалом либо локальным MCP-клиентом**. Одна ссылка
в обычной веб-переписке без выполнения кода на компьютере сотрудника архив не скачает.
Должны быть доступны рабочий стол и браузер. Существующие настройки AI-клиента
инструмент сам не меняет. Не нужно переносить аккаунты сотрудников на общий сервер.

## Установка для агента

Нужен Node.js 22+. Агент выполняет:

```sh
npm ci
node agent.mjs doctor
```

Можно использовать установленный Chrome/Edge либо Chromium:

```sh
npx playwright install chromium
```

API-ключи, платные парсеры и обращения к AI-моделям самим инструментом не нужны.
При установке загружаются публичные npm-пакеты и, при необходимости, Chromium.

## Путь без настройки MCP

Агент запускает обычную короткую команду:

```sh
node agent.mjs start --provider chatgpt --workspace work --browser chrome
```

Для Claude — `--provider claude`. `--workspace` — метка аккаунта и пространства,
например `my-work-account-team`, не пароль. При двух сервисах выгружайте последовательно.
`--out "/путь/к/архиву"` задаёт отдельную папку. По умолчанию — домашняя
`Downloads/chat-rescue/<сервис>/<метка>-<хеш>/`.

Команда возвращает JSON с `run_file`. Отдельный worker открывает свой профиль
браузера. Основной профиль сотрудника не читается и не копируется.

```sh
node agent.mjs status --run "/путь/к/архиву/run.json"
```

Когда `phase=awaiting_login`, сотрудник самостоятельно входит и выбирает workspace
**в первой вкладке этого окна**. Для SSO завершите вход возвратом в первую вкладку.
Раскройте боковую историю; в Claude откройте полный список чатов.
После сообщения сотрудника агент выполняет:

```sh
node agent.mjs continue --run "/путь/к/архиву/run.json"
```

Агент опрашивает `status` раз в несколько секунд. При окончании JSON содержит
`zip.path`, `zip.sha256`, счётчики, `index_file` и ограничения. Чаты в ответ агента
не передаются: на диск записывается текст, в CLI/MCP возвращаются только метаданные.

```sh
node agent.mjs stop --run "/путь/к/архиву/run.json"
node agent.mjs resume --run "/путь/к/архиву/run.json"
node agent.mjs pack --run "/путь/к/архиву/run.json"
node agent.mjs close --run "/путь/к/архиву/run.json"
```

`stop` оставляет браузер/worker для продолжения. `close` закрывает только свой
браузер и worker, файлы остаются. После завершения worker новый `start` с теми же
provider/workspace/out открывает архив заново; после проверки входа используйте `resume`.
Все команды работают без TTY и не ждут ручного Enter в терминале.

## MCP

Локальный сервер:

```sh
node mcp.mjs
```

Это stdio: stdout предназначен для MCP JSON-RPC, а не интерактивного терминала.
Готовый конфиг с абсолютными путями на этом компьютере:

```sh
node agent.mjs config
node agent.mjs config --client codex
```

Общий JSON-формат для совместимого клиента:

```json
{
  "mcpServers": {
    "chat_rescue": {
      "command": "node",
      "args": ["/ABSOLUTE/PATH/chat-rescue-agent/mcp.mjs"]
    }
  }
}
```

Для Codex можно добавить сервер командой ниже. [Официальная документация Codex](https://learn.chatgpt.com/docs/extend/mcp).

```sh
codex mcp add chat-rescue -- node "/ABSOLUTE/PATH/chat-rescue-agent/mcp.mjs"
```

Для Claude Code — следующая команда. [Официальная документация Claude Code](https://code.claude.com/docs/en/mcp).

```sh
claude mcp add --transport stdio chat-rescue -- node "/ABSOLUTE/PATH/chat-rescue-agent/mcp.mjs"
```

| MCP tool | Действие |
| --- | --- |
| `check_environment` | Node, браузеры и локальные требования |
| `open_export_session` | Открыть свой браузер и получить `session_id` |
| `inspect_export_session` | Готовность вкладки без текста переписок |
| `start_export` | Начать фоновый поиск/чтение/ZIP после `user_ready=true` |
| `get_export_status` | Счётчики, прогресс, ошибки и пути к файлам |
| `stop_export` | Остановить очередь |
| `resume_export` | Продолжить с проверкой SHA-256 |
| `create_export_zip` | Собрать уже сохранённое без сетевого чтения |
| `close_export_session` | Закрыть собственный браузер |

Есть MCP prompt `export_my_chats`. Долгая работа идёт в фоне: `start_export` быстро
возвращает ID, затем агент опрашивает статус. После потери/перезапуска MCP сессия
восстанавливается через тот же provider/workspace/out и `resume_export`.
CLI и MCP используют один архивный механизм, одновременно одну папку не открывают.

## Один чат, ссылки и продолжение

Для пробы агент открывает известный диалог в первой вкладке и вызывает:

```sh
node agent.mjs continue --run "/путь/run.json" --mode current
```

Для заранее известных доступных ссылок, включая проекты, подготовьте `links.txt`
с HTTPS-ссылками на чаты выбранного сервиса:

```sh
node agent.mjs continue --run "/путь/run.json" --urls-file links.txt
```

В MCP соответствуют `mode=current` либо `mode=urls, urls=[...]`. Режим по умолчанию
`all` ищет ссылки в доступном интерфейсе, добавляет их к прежней очереди и сохраняет.
Он не доказывает полноту серверной истории и не раскрывает самостоятельно каждый
скрытый проект/архивный список. Их можно открыть отдельно и снова выполнить `all`.
`refresh=true`/CLI `--refresh` перечитывает выбранные чаты, сохраняя старые версии.
Для очень длинных диалогов можно увеличить `max_scrolls` (CLI `--max-scrolls`),
для длинного списка — `list_scrolls` (`--list-scrolls`), максимум 5000. Пауза
`delay_ms` (`--delay-ms`) не меньше 1000 мс. Статус содержит до 100 конкретных
ошибок/предупреждений в `issues` и причину остановки поиска в `last_discovery`.

## Статусы и файлы

| phase | Значение |
| --- | --- |
| `opening` | Worker открывает браузер |
| `awaiting_login` | Нужен вход сотрудника и выбор пространства |
| `discovering`, `exporting` | Фоновая работа |
| `complete` | Выбранная очередь обработана; полнота аккаунта не подтверждена |
| `needs_review` | Есть частичные записи или проблемы целостности |
| `paused` | Остановка или лимит новых чтений; см. `stop_reason` |
| `blocked` | Явный отказ доступа; автоматического повтора нет |
| `failed`, `interrupted` | Ошибка/завершённый worker; данные сохраняются |

В папке архива: `INDEX.md`, `manifest.json`, `chats/*.md`, `chats/*.json`, версии и ZIP.
`run.json` — только управление/статус. ZIP содержит переписки, индекс, manifest и
`EXPORT-ISSUES.json`; профиль входа, `.commands`, конфиги запуска и логи исключены.
Внутри ZIP текущие и исторические версии проверяются по SHA-256. Несовпадение
фиксируется явно, без заявления о корректном полном архиве.

Профиль входа: `~/.chat-rescue-agent/profiles/`. Не пересылайте его вместе с кодом.
Нет HTTP-сервера, открытого CDP-порта, удалённого загрузчика архивов или аналитики.
MCP/CLI управляют только собственной сессией инструмента.

## Ограничения и проверка

**14/14 автоматических проверок прошли.** Подробные доказательства и границы —
в [QA.md](QA.md).

Живой экспорт корпоративного аккаунта пока не проверен: сотрудник ранее сообщил,
что сейчас не может войти. Синтетические browser/MCP тесты это не заменяют.
До отключения доступа сравните один сохранённый диалог с оригиналом.
Нельзя гарантировать все архивные чаты, проекты и полноту текста только по DOM.
Бинарные вложения, картинки, документы, Canvas/Artifacts, скрытые блоки, инструкции
проектов и другие ветки скачайте отдельно. Доступ после отключения не восстанавливается.

При 401/403/429/498 навигации очередь останавливается. Никакого обхода CAPTCHA,
SSO/админских ограничений или ротации IP. Обычный сайт может ограничить автоматизацию.
Сохранённый архив предназначен для чтения; перенос истории в другой аккаунт не реализован.

Для Claude доступен и штатный экспорт сотрудника, если Owner разрешит его в
Organization settings → Data and privacy. [Официальная инструкция Claude](https://privacy.claude.com/en/articles/9450526-export-your-claude-data).

```sh
npm test
npm run build
```

Тесты используют настоящий SDK-клиент и stdio-сервер, собственный Chromium,
изолированные профили и offline-страницы. Производственные entry point не имеют
режима подмены сайтов: тестовая фабрика подключается только из `test/`.
Платных API/AI вызовов нет. Сборка выдаёт готовый ZIP исходников, пригодный для
передачи агенту или размещения в отдельном Git-репозитории. Основа MCP —
[официальный TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server).
