# Проверка Chat Rescue Agent 1.3.0 — 03.11.2026

**57/57 автоматических проверок прошли**: прежние 43 и 14 регрессий надёжности.
macOS arm64, Node.js 24.15.0, Playwright 1.64.0, настоящий Chromium и stdio MCP.

## Основание изменения

Пользователь сообщил о неудачной выгрузке ChatGPT на macOS: ожидалось 5 чатов,
получились 0 полных, 2 частичных и 1 ошибка; роли не распознаны, при чтении
обнаружена другая страница. На скриншоте агент также закончил ответ после запуска
worker, до проверки архива. Скриншот не содержит технических логов или HTML сотрудника.

В коде воспроизведена гонка Apple Events: после присвоения URL loading=false может
ещё относиться к старому документу. Это доказанный дефект адаптера; точная причина
каждой ошибки на аккаунте сотрудника и живой успешный повтор пока не установлены.

## Что проверено

- Задержанный переход macOS: loading=false при старом адресе не завершает goto.
  Вкладка выбирается по уникальной about:blank-метке; источник не закрывается.
- Пять ChatGPT-диалогов с полностью отсутствующими DOM-атрибутами ролей сохранены
  по реально наблюдённым JSON-ответам интерфейса: 5 saved, 0 partial, 0 failed.
- Совмещённый прогон через NativeMacPage + моделируемый Apple Events bridge и
  настоящий DOM/SPA Chromium также завершил все пять чатов по пассивному fetch.
  Итоговый ZIP независимо открыт Python zipfile: CRC, пять JSON и роли проверены.
- Пассивный fetch сохраняет исходный Promise/заголовки приложения и не создаёт
  дополнительных GET. Тестовая UI-загрузка требует свой Authorization; экспортёр
  его не читает и не переносит. Работает копия JSON-ответа, полученного самим UI.
- ID JSON обязан совпасть с выбранным чатом. Чужая запись не принимается.
  Начавшаяся загрузка нового диалога блокирует сохранение старого DOM даже после
  изменения адреса. Динамическая смена страницы в середине чтения исправляется
  одним безопасным повтором в своей вкладке; чужой текст не попадает в запись.
- Распознаются явные data-атрибуты и доступные подписи автора ChatGPT; роли не
  угадываются по чередованию. Несколько Markdown-блоков сообщения не обрезаются.
- Последовательность 2 partial + 1 ошибка + 2 доступных чата сохраняет последние два:
  2 saved, 2 partial, 1 failed, 0 pending. Недоступное не объявляется сохранённым.
- Отказ 403 в JSON-ответе самого UI останавливает очередь без повтора и чтения
  следующего чата. Сохранённое автоматически упаковывается.
- При упаковке, в том числе после ошибки, статус finalizing ещё не финальный.
  Терминальный статус возвращается только после записи ZIP. Отдельная искусственная
  задержка упаковки проверяет эту гонку. SHA-256 ZIP проверяется чтением с диска;
  повреждённый ZIP не подтверждается как успешный.
- Производственная scrape теперь возвращает финальный проверенный результат,
  а не только opening/job_id. Старый worker обновляется только в состоянии простоя
  через его собственный close; сохранённые чаты остаются.
- diagnose/diagnostics.json содержат версию, способ подключения, коды, хеши ID и
  счётчики; содержимое переписок, cookies и Authorization в них не включены.

## Границы подтверждения

Сетевые ответы и аккаунты в браузерных регрессиях синтетические; браузер offline.
NativeMacPage проверен с настоящим DOM и моделируемым мостом, JXA компилируется
штатным osacompile. Настоящий экспорт на проблемном корпоративном аккаунте и живой
Apple Events диалог разрешения не проверены. Нельзя называть эти тесты доказательством
устранения всех сбоев у сотрудника или гарантией полноты его корпоративной истории.
Следующий живой сбой должен сопровождаться `diagnose --run ...`, а не только
сообщением модели. Пароли и текст переписок для этого не нужны.

- Полные пакеты: SKILL.md, скрипты, бинарные ресурсы и права запуска файлов.
  Код Skills не исполняется; содержимое не попадает в метаданные CLI/MCP.
- Ссылки на папки Skills поддерживаются, ссылки из Skill наружу пропускаются с отметкой.
  Отдельно проверены лимит размера и исключение локальных конфигов/кэшей.
- Оригинальные веб-ZIP сохраняются без переписывания: перехвачен Blob в собственной
  рабочей вкладке либо прочитана наблюдённая ссылка скачивания того же origin.
  Прокрутка списка, меню Download и задержанная отрисовка проверены реальным DOM.
- Отказ 403 прекращает веб-очередь без повтора и чтения следующего Skill. Внешняя
  ссылка не получает cookies; HTML, повреждённый ZIP, traversal и ZIP без SKILL.md
  не становятся успешным пакетом. Проверяются CRC и размеры файлов ZIP.
- Недоступный Claude не мешает упаковать локальные Skills. После остановки остаётся
  архив сохранённого. Повтор не затирает старый ZIP; результат внутри Skill не копируется.
- Производственная CLI-команда и настоящая фоновая задача MCP проверены отдельно.
  Теперь MCP предоставляет 12 tools; прежние инструменты и имена сохраняются.

## Реальный локальный прогон

Производственная `skills --provider codex` проверена на имеющихся локальных Skills:
84 пакета, из них 82 saved, 2 partial, 0 failed. Размер общего ZIP — 64 049 067 байт.

# Проверка Chat Rescue Agent 1.1.0 — 03.11.2026

## Новый основной сценарий: уже открытая сессия

**28/28 автоматических проверок прошли**, без пропусков на macOS arm64,
Node.js 24.15.0, Playwright 1.64.0. Существующие 14 проверок режима отдельного профиля
сохранены; добавлены 14 проверок подключения к текущему браузеру.

Проверено в реальном Chromium и по настоящему локальному CDP:

- Обычная сессия браузера заранее содержит искусственную авторизационную cookie.
  Сервер тестовой страницы требует её; без неё показывает вход. Инструмент не
  читает cookies: его рабочая вкладка наследует существующий браузерный контекст.
- `open_export_session` сразу начинает поиск, сохраняет два чата и собирает ZIP.
  Нет дополнительного `start_export`, `continue` или подтверждения `user_ready`.
- Производственная команда `node agent.mjs export` запускает отдельный worker и
  действительно завершает сохранение текущего чата без TTY и ручного продолжения.
- Подключение через WebSocket из DevToolsActivePort не зависит от `/json/version`.
  Разрешены только loopback-адреса; посторонние адреса и credentials отклоняются.
- Исходная вкладка, её URL и браузер остаются открытыми после экспорта и после
  остановки активной задачи. Закрываются только рабочая вкладка и CDP-соединение.
- Отсутствующая вкладка и окно входа не вызывают fallback в отдельный пустой профиль.
  При signin-модальном окне в архив не записывается фиктивный успешный диалог.
- Медленный клиентский рендеринг ожидается до появления истории: временно пустая
  страница не принимается за потерянный вход. Это проверено отдельной задержанной страницей.
- При нескольких вкладках выбирается активная, а неоднозначность возвращается
  как `source_tab_required`, без угадывания аккаунта.
- Для macOS нативный адаптер проверен через моделируемый мост и настоящий DOM
  Chromium: сначала проверяется разрешение, затем создаётся рабочая вкладка в
  выбранном окне. При запрете новая вкладка не создаётся. JXA-код компилируется
  штатным `osacompile` без доступа к браузеру пользователя.

Браузер в этих тестах работает offline. Страницы, аккаунт и cookie искусственные.
